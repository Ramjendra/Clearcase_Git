WHAT WE BUILT
=============

A Python-based automated pipeline that migrates source code from
IBM ClearCase (old version control) to GitHub — preserving full
history, branches, labels, and author information.


THE 5-AGENT PIPELINE
====================

  ClearCase --> [1 Discover] --> [2 History] --> [3 Extract]
            --> [4 Convert] --> [5 Publish] --> GitHub

  Agent 1: Discovery Agent
    - Scans the ClearCase VOB (vault)
    - Maps all files, branches, and labels

  Agent 2: History Agent
    - Reads every file version
    - Groups versions into logical git commits
    - Groups by: author + time window + comment

  Agent 3: Extractor Agent
    - Fetches actual file content from ClearCase
    - Handles C/C++ files and encoding detection
    - Handles large binary files via Git LFS

  Agent 4: Git Conversion Agent
    - Writes full git history using git fast-import
    - Very fast — handles millions of versions
    - Creates branches and tags

  Agent 5: Publisher Agent
    - Creates the GitHub repository
    - Pushes all branches and tags


WHAT WAS TESTED
===============

We ran a full end-to-end test WITHOUT needing a real ClearCase
server — using a Mock client and sample VOB data.


Test 1: C File Analysis (CFileAgent)
-------------------------------------
Scanned all sample C/C++ source files and auto-fixed
ClearCase-specific artifacts:

  cc_keywords     - Strips ClearCase version strings like $Id$,
                    $Revision$ embedded in source code

  cc_include_ext  - Fixes broken #include paths like
                    "utils.h@@/main/5" --> "utils.h"

  view_root_path  - Replaces hardcoded /view/my_view/vobs/ paths
                    with relative portable paths

  makefile_cc_var - Replaces CLEARCASE_ROOT variables in Makefiles
                    with portable $(REPO_ROOT)

  merge_conflict  - Detects unresolved ClearCase merge markers
                    (flagged for manual review)

  pragma_ident    - Detects #pragma ident ClearCase version strings
                    (preserved for audit trail)

  Result: 10 source files scanned, issues auto-fixed,
          full report saved to logs_test/c_file_issues.md

KEY FEATURES
============

  - No history loss        Every version, branch, label migrated
  - Author mapping         CC usernames --> real names + emails
                           (configured in authors.csv)
  - Resume support         If interrupted, picks up where it stopped
  - Dry-run mode           Plan migration without writing anything
  - Large file support     Binary files >50MB handled via Git LFS
  - Fully automated        Single command to run entire pipeline


HOW TO RUN (Production)
========================

Step 1: Edit config.yaml
    - Set ClearCase VOB tags and view name
    - Set GitHub org/repo name

Step 2: Edit authors.csv
    - Map ClearCase usernames to real names and emails

Step 3: Set GitHub token
    - export GITHUB_TOKEN=ghp_xxxxxxxx

Step 4: Run the pipeline
    - python3 main.py --config config.yaml

Optional flags:
    --dry-run       Plan only, no writes
    --no-resume     Start fresh
    --skip-to       Jump to a specific stage
    --debug         Verbose logging
